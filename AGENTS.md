# rgitweb

A fully static, client-side Git repository browser — a cgit replacement that
needs no server-side logic at all. The built output is plain static files.

## Why it works the way it does

The app reads the same data a `git clone` over dumb HTTP would read, directly
from the browser, but only as much as is needed to render the current page:

- `info/refs`, `HEAD`, and `objects/info/packs` are small plain-text files
  maintained by `git update-server-info` on the server.
- Loose objects are fetched individually and zlib-inflated in the browser.
- Pack files are never downloaded whole: the `.idx` v2 index locates an
  object's offset (fanout table + binary search over the sorted SHA table),
  then a **HTTP Range request** fetches just that object's record from the
  `.pack`. Packs are content-addressed and immutable, so the browser HTTP
  cache makes repeated range reads cheap. This is why the transport layer
  must not add cache-busting headers.
- Deltified objects (ofs-delta / ref-delta) are resolved recursively against
  their base objects.

The target repository's server must send CORS headers (including exposing
`Accept-Ranges`/`Content-Range`); the UI surfaces a clear error when it does
not. There is no smart-HTTP support on purpose: smart HTTP requires POST
endpoints, which static hosting cannot provide.

## Structure

- `src/git/` — pure TypeScript Git data layer. No React, no DOM beyond
  `fetch`/WebCrypto/`DecompressionStream`-safe APIs. The public surface is
  defined in `src/git/types.ts` and re-exported from `src/git/index.ts`;
  UI code imports only from `src/git/index.ts`.
- `src/ui/` — React SPA with hash-based routing
  (`#/<encoded-repo-url>/<page>/...`), so the site works from any static
  host without URL rewriting.
- `test/` — Jest tests. Git-layer tests run against fixture repositories
  generated by real `git` (see `test/fixtures/`), not hand-built binaries,
  so the parsers are validated against authoritative output.

## Git layer semantics worth knowing

These are true of the implementation but not obvious from `types.ts`:

- `Repository.resolve()` does **not** peel annotated tags: it returns the tag
  object's own oid. UI code that needs a commit peels explicitly (see
  `src/ui/utils/resolveCommit.ts`).
- `log(start)` yields `start` itself as its first item. The log page's
  `?from=` pagination cursor relies on this inclusivity; making the walk
  exclusive would silently break "older" pages rather than erroring.
- `getCommit`/`getTree` throw a plain `Error` (not `NotFoundError`) when the
  oid exists but has the wrong type.
- Raw tree objects store directory modes unpadded (`40000`); `git ls-tree`
  displays them padded (`040000`). `TreeEntry.mode` follows the raw format.

## Start page

The start page (`src/ui/pages/StartPage.tsx`) does not take an arbitrary
repository URL — most Git hosts don't send the CORS headers this app needs,
so a free-text box mostly produces CORS errors rather than a working demo.
It lists only repositories from `src/ui/featuredRepos.ts`, which reads the
`VITE_FEATURED_REPOS` build-time environment variable (a JSON array of
`{"name", "url"}`) and falls back to an empty list. `.github/workflows/deploy.yml`
sets this to point at a copy of this repository's own history, published
alongside the site itself (see below).

## Example deployment

`.github/workflows/deploy.yml` builds the site and deploys it to GitHub
Pages as a working demo of the project: it copies this repository's `.git`
directory into the build output, runs `git update-server-info` on the copy,
and strips `config`/`hooks`/`logs`/`index` (not read by the dumb-HTTP layer,
and `config` would otherwise carry the checkout step's short-lived
`GITHUB_TOKEN` credential onto a public URL — checkout uses
`persist-credentials: false` for the same reason). The featured-repo list
points at that copy, so the deployed site can browse its own source without
depending on any third-party host's CORS configuration.

## Conventions

- npm, ES modules only, strict TypeScript, no enums.
- Lint/format via `eslint-config-andrewaylett` (Prettier through ESLint);
  run `npm run lint:fix` rather than a separate formatter.
- Tests: `npm test` (Jest with ESM). Build: `npm run build`.
- Temporary files belong in the build output directory (`build/`).
